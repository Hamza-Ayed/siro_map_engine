# دراسة الجدوى: تضاريس 3D على الموبايل / Terrain feasibility (N-08)

## الحقائق / Facts (checked in the SDK files)

- **Android، MapLibre 13.5.0:** الـ SDK يعرض `RasterDemSource` (مصدر DEM، لطبقة hillshade). ما في API عام في `Style` للتضاريس ثلاثية الأبعاد (`setTerrain` أو ما شابه). تم التحقق من الـ `classes.jar` داخل الـ AAR.
- **iOS، MapLibre 6.28.0:** الـ framework يعرض `MLNRasterDEMSource`. ما في header فيه `setTerrain`، ولا `MLNTerrain`. تم التحقق من الـ Headers.
- **النتيجة:** التضاريس ثلاثية الأبعاد غير متاحة في الـ API العام لأي من المنصتين بالإصدار المثبّت. الـ DEM متاح فقط لـ hillshade.

## الخيارات / Options

1. **WebView + maplibre-gl-js (المخطط، D-004):** حزمة `siro_gl_terrain` لسا ما انعملت (المرحلة D). تحتاج ملف maplibre-gl-js محلي (D-T0)، وقرار على الحزم الجديدة (`shelf` بموافقة).
2. **بناء فرع من المحرك الأصلي (N-02، N-03 ثم تعديل C++):** ممكن، لكن كلفته عالية: مكونات DEM، mesh، depth، تعديل symbol placement، والكاميرا. تقدير بأسابيع عمل، وتتطلب بناء المحرك من المصدر (أدوات وتحميل مستودع كبير).
3. **انتظار إصدار أحدث من MapLibre Native:** غير معروف متى، وما في وعد من المشروع. يحتاج تحقق من الـ issues والـ PRs قبل القرار.

## التوصية / Recommendation

ابدأ بالخيار 1 لتجربة المنتج، وخلي الخيار 2 قرار منفصل بعد ما نقيس الحاجة الحقيقية. هذا القرار لصاحب المشروع (N-08: "وقّف هون").
